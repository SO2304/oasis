OASIS: a signed multi-hop mesh kernel for low-cost sensor nodes

Rust, no_std. Per-node Ed25519 origin signatures, replay protection and revocation for multi-hop mesh networks, running on a Cortex-M0+ (RP2040) with 119 KB of flash. Validated on silicon. Not yet audited, not certified, not power-optimised.

pre-1.0 · single maintainer last silicon run 2026-10-06 3 × RP2040 · 9/9 suite runs green host: 444 unit tests · 113 Kani harnesses

§1Problem

Most low-cost sensor meshes authenticate traffic with a key shared by every node. Capturing one node gives an attacker that key, and with it the ability to impersonate any other node, inject commands in their name and replay old traffic. Cheap nodes deployed in the field are exactly the ones that get lost, stolen or opened.

OASIS gives each node its own signing identity. A captured node can sign only as itself, can be revoked, and cannot replay other nodes' messages.

§3Architecture

Application

Sensor payloads, commands, or MAVLink v2 traffic (CRC, signing, replay checks) when bridged to a PX4 autopilot.

Safety gate (R14)

Entropy-based gate: no actuation while sensor-derived uncertainty is above a threshold. Sensor loss raises entropy and freezes actuation.

Transport security

AEAD envelopes, ephemeral and static Diffie-Hellman for forward secrecy and sender authentication, replay window, signed revocation. Standard primitives only, no custom cryptography.

Mesh

Multi-hop flooding with TTL and dedup. Three header modes: unsigned (trusted bus), keyed MAC (external attacker), per-node signature (insider). The mesh header is authenticated; payload integrity is the transport layer's job.

Link

Transport trait. Wired UART validated on silicon. LoRa SX1262 driver written and tested against a mock; not yet on radio hardware. Airtime calculator and EU868 duty-cycle throttle implemented.

Three-node relay over a physical link

  • A → B → C over wired UART, per-node signatures verified at B and at C, same message id end-to-end
  • Replay: second copy dropped at the first hop, never relayed
  • Forged origin injected mid-path: dropped by the next node
  • TTL exhaustion: delivered, not forwarded
  • 600-packet burst: no crash on any node

Fault injection, 200 packets

  • Wire noise up to 20 % bit-flip and 15 % drop: all corruption caught by the frame CRC, before the verifier
  • Single-bit flips injected before the CRC: every flip in a signed field was rejected (34 by crypto, 4 by the parser)
  • No crash, no reset on any board

Finding from that test: 12/50 flips landed in payload or hop fields and were accepted, because the v0A signature covered the header only. Fixed in v0B (below).

v0B: content, freshness and network bound into the signature

  • Signed: origin, counter, network id, payload length and SHA-256 of the payload
  • Relay state changes only after full verification
  • Per-origin counter window persisted in flash
  • Strict: legacy envelopes refused (no downgrade)
  • Cost over v0A: +1 % sign, +0.7 % verify on the chip

v0B on silicon (2026-10-06)

  • Pre-CRC single-bit flips: 0 accepted of 147 logged (v0A: 12/50)
  • Payload swapped by a relay, signature kept: dropped, genuine message still delivered
  • Relay power-cut: counter window restored from flash, old counter refused
  • Pending: re-run in strict mode, byte-exact replay, sender counter lease
